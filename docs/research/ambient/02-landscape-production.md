# 02 — Production landscape: ambient & proactive agents as shipped (2026-08)

Research agent report, 2026-08-25. Scope: shipped systems that do useful work
while the user is not chatting — scheduled prompts, event watchers, standing
intents, sleep-time processing, and proactive contact — with mechanical detail
(trigger firing, state location, scheduling, result delivery), a
trigger-architecture comparison, and mechanisms transferable to this
single-process FastAPI + Postgres + LangGraph platform.

## 1. OpenAI

### 1.1 ChatGPT Scheduled Tasks (Jan 2025; relaunched June 17, 2026)

**Mechanics.** A task = a saved prompt + a schedule (daily/weekly/custom cadence), stored server-side against the user's account. Each firing is a *brand-new execution* — it does not carry the originating conversation's context forward ([usecarly.com](https://www.usecarly.com/blog/chatgpt-scheduled-tasks/)). On fire, ChatGPT runs the prompt (with web browsing and, post-relaunch, connected apps), writes the result into a new chat, and surfaces an in-app notification; if the user enabled email or push in Settings → Notifications, they also get an email/mobile push at the scheduled time ([help.openai.com](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt), [ai-toolbox.co](https://www.ai-toolbox.co/chatgpt-management-and-productivity/how-to-use-chatgpt-tasks-schedule-2026)).

**The June 2026 relaunch added "monitoring tasks"** — standing intents: ChatGPT periodically checks the web or connected apps and notifies *only when the model judges a change significant*, not on every check. A dedicated "Scheduled" sidebar page lists tasks with next-run times and pause/resume/edit/delete ([aiweekly.co](https://aiweekly.co/alerts/openai-brings-scheduled-tasks-and-web-monitoring-to-chatgpt), [enterprisedna.co](https://enterprisedna.co/resources/news/openai-chatgpt-scheduled-tasks-autonomous-business-automation-2026/)).

**Concrete limits.** Active-task caps by plan: Go 3, Plus 5, Business/Edu 10, Pro/Enterprise 15 ([help.openai.com](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt)). Frequency floor ~once per hour; unattended tasks may auto-pause after inactivity ([usecarly.com](https://www.usecarly.com/blog/chatgpt-scheduled-tasks/), [aiweekly.co](https://aiweekly.co/alerts/openai-brings-scheduled-tasks-and-web-monitoring-to-chatgpt)). No voice, file uploads, or Custom GPTs inside a task; output can't automatically trigger downstream workflows ([usecarly.com](https://www.usecarly.com/blog/chatgpt-scheduled-tasks/)).

### 1.2 ChatGPT Pulse (Sept 25, 2025 → retired June 2026)

Pulse was the fully-proactive experiment: overnight asynchronous research synthesizing memory, chat history, feedback, and connected apps (Gmail/Google Calendar, off by default) into a morning digest of visual topic cards; user thumbs-up/down curated future research ([openai.com](https://openai.com/index/introducing-chatgpt-pulse/), [androidauthority.com](https://www.androidauthority.com/chatgpt-pulse-launched-3601783/)). Launched as mobile preview on the $200/mo Pro tier, expanded to web in Oct 2025, never reached Plus/free, and was retired in June 2026 with its functionality folded into scheduled/monitoring tasks — a shift from "AI decides what to research" to "user declares standing intents with explicit control" ([prowlo.com](https://prowlo.com/blog/chatgpt-pulse-shut-down), [bleepingcomputer.com](https://www.bleepingcomputer.com/news/artificial-intelligence/chatgpt-pulse-is-coming-to-the-web-but-no-word-on-free-or-plus-roll-out/)). **Lesson: the digest-card + feedback-loop UX survived; the opaque autonomous-topic-selection did not.**

### 1.3 Agent Mode / Operator

Agent mode (browser + code interpreter + file editing in a sandboxed VM) is session-bound: if the session ends, the agent cannot continue in the background — a widely-criticized gap ([techradar.com](https://www.techradar.com/ai-platforms-assistants/chatgpt/i-cant-actually-keep-working-on-a-long-manual-task-like-this-in-the-background-once-a-message-turn-ends-chatgpt-has-a-major-limitation-that-needs-to-be-addressed-and-fast)). Plus ≈ 30–40 agent uses/month; only initial requests count, not clarifications ([help.openai.com](https://help.openai.com/en/articles/11752874-chatgpt-agent)). Safety model (transferable): explicit **confirmation before consequential actions** (purchases, sending email); **watch mode** — on sensitive sites (email, banking) the agent requires the user actively supervising and stops taking screenshots; **takeover mode** — user enters credentials/payment directly, model never sees them ([help.openai.com](https://help.openai.com/en/articles/10421097), [openai.com](https://openai.com/index/introducing-chatgpt-agent/)).

## 2. Anthropic

### 2.1 Claude Code Routines (research preview, ~April 2026) — the most fully-specified production design

A routine = saved config: **prompt + repositories + connectors + environment + triggers**, stored on the user's claude.ai account; each fire creates a fresh autonomous cloud session (no permission prompts mid-run) on Anthropic-managed VMs ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)). Mechanics worth copying verbatim:

- **Three composable trigger types on one routine**: Scheduled (presets hourly/daily/weekdays/weekly, custom cron via CLI, **minimum interval 1 hour**, one-off runs at a timestamp that auto-disable after firing); **API** (per-routine `/fire` HTTPS endpoint + per-routine bearer token, shown once, revocable/rotatable; returns `{session_id, session_url}` so the caller can watch the run live); **GitHub events** (pull_request and release categories, with filters on author/title/body/base/head/labels/draft/merged using equals/contains/starts-with/one-of/regex operators; per-routine and per-account **hourly webhook caps — excess events are dropped**) ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).
- **Prompt-injection discipline at the trigger boundary**: the saved prompt is trusted (it "attests only that the prompt was stored ahead of time by an authorized session"), but the `/fire` payload `text` arrives wrapped in a `<routine-fire-payload>` block **labeled untrusted** — the routine's prompt must explicitly opt in to acting on it, so a leaked bearer token can't inject instructions ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).
- **Blast-radius controls**: pushes only to `claude/`-prefixed branches unless the target is unprotected, has no one else's open PR, and carries no commits authored by others; environments carry a network **allowlist** (Trusted default → 403 + `x-deny-reason: host_not_allowed` off-list); connectors default-on but removable per routine ("Claude can use every tool from an included connector, including writes, without asking") ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).
- **Scheduling details**: local-time entry converted to UTC; **runs stagger a few minutes with a consistent per-routine offset** (thundering-herd control); daily per-account run cap with metered overage opt-in; one-off runs exempt from the cap; explicit warning that a **green run status means "no infrastructure error," not task success** — reading the transcript is the verification ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).
- Results reach the user as ordinary sessions in the session list (review changes, open a PR, continue the conversation). CLI `/schedule why did my nightly review do nothing this morning?` makes the agent itself the run-history debugger ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).

Claude Code has four "keep working without watching" mechanisms — Agent View, headless mode, `/loop`, Routines — and only Routines survive the laptop closing ([wmedia.es](https://wmedia.es/en/tips/claude-code-background-agents-map)). PR watching is separately available as in-session subscriptions that deliver GitHub webhook events (comments, CI failures, check-suite rollups) into a live session as wake events ([claudedirectory.org](https://www.claudedirectory.org/blog/claude-code-routines-guide)).

### 2.2 Claude Tag in Slack (beta June 23, 2026)

Persistent multiplayer agent living in Slack channels with channel-scoped memory; runs multi-step work asynchronously over hours/days. **Ambient mode is opt-in**: Claude monitors all messages in connected channels continuously and posts on its own initiative — surfacing relevant information, following up on threads/tasks that went quiet — without being tagged; it cannot read private channels it wasn't granted ([techtimes.com](https://www.techtimes.com/articles/319206/20260627/claude-tag-brings-ambient-ai-slack-admins-have-until-august-3-migrate.htm), [thenextweb.com](https://thenextweb.com/news/anthropic-claude-tag-slack-always-on-ai-teammate)). Anthropic's own launch guidance: **start with ambient mode disabled until the team understands the failure modes** ([usecarly.com](https://www.usecarly.com/blog/claude-slack-integration/)).

### 2.3 MCP watcher/subscription patterns

The MCP spec has a built-in pub/sub shape: client sends `resources/subscribe` for a URI; server pushes `notifications/resources/updated` (a **payload-free "something changed" ping** — client then does `resources/read`), plus `notifications/resources/list_changed` for roster changes; servers declare `subscribe`/`listChanged` capabilities ([modelcontextprotocol.io](https://modelcontextprotocol.io/specification/2026-07-28/server/resources), [apxml.com](https://apxml.com/courses/getting-started-model-context-protocol/chapter-2-defining-resources-and-prompts/resource-subscriptions-notifications)). Server-side, the notification is typically fed by a filesystem watcher, DB trigger, or external event loop ([mcp-observer discussion](https://github.com/orgs/modelcontextprotocol/discussions/391)). Caveat from practice: notifications only flow while a session is open, so MCP alone doesn't give you durable "watch my inbox" — the host needs a persistent listener process ([ankitmundada.medium.com](https://ankitmundada.medium.com/mcp-has-notifications-so-why-cant-your-agent-watch-your-inbox-bb688fde7ac5)).

## 3. Letta sleep-time agents

**Mechanics.** Creating a sleeptime-enabled agent actually creates two agents in a shared **group** over shared memory blocks: the primary agent converses and *cannot* edit its own core memory; the **sleep-time agent** owns rewriting both the primary's in-context memory blocks and its own ([docs.letta.com](https://docs.letta.com/guides/agents/architectures/sleeptime/)). Trigger: the sleep-time agent fires **every N primary-agent steps — `sleeptime_agent_frequency`, default 5** — asynchronously, so memory reorganization happens off the latency path; it can also run when context is compacted or after a set number of completed steps in newer releases, with an optional second background "agent reviews before applying" pass on proposed memory edits ([docs.letta.com](https://docs.letta.com/guides/agents/architectures/sleeptime/), [forum.letta.com](https://forum.letta.com/t/sleeptime-agents-for-memory-consolidation-best-practices-guide/154)).

**Why (numbers).** The Sleep-time Compute paper (arXiv 2504.13171): precomputing "learned context" during idle time cuts test-time compute needed for the same accuracy **~5×** on Stateful GSM-Symbolic/AIME, raises accuracy up to **13–18%** when scaled, and amortizing across related queries cuts cost **~2.5×** ([arxiv.org](https://arxiv.org/html/2504.13171v1), [letta.com](https://www.letta.com/blog/sleep-time-compute/)). This is the strongest published quantitative case for the consolidation-jobs subsystem.

## 4. LangChain / LangGraph ambient agents

**Concept.** LangChain's definition: "ambient agents listen to an event stream and act on it accordingly, potentially acting on multiple events at a time," with exactly three HITL patterns — **Notify** (flag, don't act), **Question** (ask instead of hallucinate), **Review** (approve/edit/give-feedback before a consequential action) — surfaced in an **Agent Inbox**, an email/ticketing-style UI centralizing all pending agent↔human interactions ([langchain.com blog](https://www.langchain.com/blog/introducing-ambient-agents)).

**Reference implementation — executive-ai-assistant (EAIA).** Gmail ingestion is **cron-driven polling**: `scripts/run_ingest.py --minutes-since 120 --rerun 1 --early 0` pulls mail from a lookback window with early-termination on already-seen messages; `scripts/setup_cron.py` registers the poll as a LangGraph Platform cron. Graph: triage (ignore / notify / draft) → draft-response / calendar logic → **interrupt** for human review in Agent Inbox → send; reflection graphs update long-term memory from human edits ([github.com/langchain-ai/executive-ai-assistant](https://github.com/langchain-ai/executive-ai-assistant)). Teaching versions: [agents-from-scratch](https://github.com/langchain-ai/agents-from-scratch) and [ambient-agent-101](https://github.com/langchain-ai/ambient-agent-101).

**Platform mechanics.** LangGraph Platform crons: standard cron expressions **interpreted in UTC**; **thread-bound crons** (re-fire same input into one persistent thread) vs **stateless crons** (fresh thread per run, `on_run_completed: "delete"|"keep"`, delete is default; keep needs TTL/manual cleanup); orphaned crons keep billing until deleted ([docs.langchain.com](https://docs.langchain.com/langgraph-platform/cron-jobs)). HITL: `interrupt()` persists graph state via the checkpointer so execution pauses indefinitely and resumes with human input ([docs.langchain.com](https://docs.langchain.com/oss/python/langchain/human-in-the-loop), [langchain.com](https://www.langchain.com/blog/making-it-easier-to-build-human-in-the-loop-agents-with-interrupt)). Platform pricing: **$0.001/node executed**, standby $0.0007/min (dev) or $0.0036/min (prod); Developer tier 100k node-executions/mo self-hosted free ([zenml.io](https://www.zenml.io/blog/langgraph-pricing), [truefoundry.com](https://www.truefoundry.com/blog/langgraph-pricing)). All of this (crons, queue, interrupts-over-checkpoints) is exactly what this platform must replicate in-process.

**Inbox Zero** ([github.com/elie222/inbox-zero](https://github.com/elie222/inbox-zero)) — open-source production email agent: plain-English rules file ("Cursor rules for email") compiled into matching rules; on inbound mail, matched rules execute AI-chosen actions (draft reply, label, archive, forward, mark spam, **call a webhook**), with executed rules + actions persisted to Postgres via Prisma as an audit trail, and per-rule automation levels (ask-first vs fully-automated) ([ARCHITECTURE.md](https://github.com/elie222/inbox-zero/blob/main/ARCHITECTURE.md), [getinboxzero.com](https://www.getinboxzero.com/)).

## 5. Google, Microsoft, Apple

**Gemini Scheduled Actions** (June 2025+): NL-scheduled prompts ("summarize my unread emails every morning at 7am") confirmed with an inline card; results arrive as Gemini app notifications. Limits: **max 10 active scheduled actions**; paid tiers only (AI Pro/Ultra, qualifying Workspace); location triggers frozen to creation location; **responses are pre-computed ahead of delivery time**, so fast-moving data is stale on arrival — an honest engineering tradeoff (delivery SLA over freshness) worth noting ([support.google.com](https://support.google.com/gemini/answer/16316416), [androidpolice.com](https://www.androidpolice.com/geminis-scheduled-actions/), [datastudios.org](https://www.datastudios.org/post/google-gemini-s-new-scheduled-actions-what-it-is-how-it-works-and-why-it-matters)). **Project Astra** remains a research prototype for the proactive/ambient end (camera+screen perception, cross-session memory, can initiate conversation); capabilities are drip-fed into Gemini Live, no full public rollout as of early 2026 ([deepmind.google](https://deepmind.google/models/project-astra/), [blog.google](https://blog.google/technology/google-deepmind/gemini-universal-ai-assistant/)).

**Microsoft Copilot**: instructive churn — "Copilot Actions" announced Ignite 2024, previewed early 2025, **removed by May 2025**, then re-shipped as "scheduled prompts": hover a good prompt → "Schedule this prompt" → recurring automation with **max 10 scheduled prompts per user**; output lands as Copilot chat + notification ([perspectives.plus](https://www.perspectives.plus/p/the-secret-life-of-copilot-scheduled-prompts), [m365admin.handsontek.net](https://m365admin.handsontek.net/microsoft-copilot-microsoft-365-scheduled-prompts-agents/)). Agent Builder scheduled workflows (hourly/daily/weekly/monthly/yearly) GA worldwide May 2026, no admin action required ([m365admin.handsontek.net](https://m365admin.handsontek.net/microsoft-365-copilot-schedule-prompts-agent-builder/)). Enterprise commentary now focuses on the operating-model problem: scheduled agents acting under a user's delegated identity need ownership/review processes ([gethynellis.com](https://www.gethynellis.com/2026/08/scheduled-copilot-agents-operating-model/)).

**Apple**: proactive suggestions remain on-device and shallow — one-tap contextual suggestions in Messages, proactive notifications, screen-aware Siri AI (2026), with local processing as the privacy story; no user-programmable standing intents ([apple.com newsroom](https://www.apple.com/newsroom/2026/06/apple-introduces-siri-ai-a-profoundly-more-capable-and-personal-assistant/), [apple.com](https://www.apple.com/newsroom/2026/06/apple-intelligence-brings-powerful-ai-capabilities-into-everyday-experiences/)).

## 6. Home automation & no-broker eventing substrates

### 6.1 Home Assistant — the largest deployed event-driven LLM-agent host

LLMs are **conversation entities** invoked *by* the deterministic automation engine: an automation's trigger (state change, motion, schedule) fires, and a step feeds context to the AI agent for a decision or annotation; 2025.8 added **AI Tasks** (automation calls an AI task entity, e.g. "identify what caused motion on this camera") and agent-initiated conversation ("garage door open — close it?") ([home-assistant.io](https://www.home-assistant.io/blog/2024/06/07/ai-agents-for-the-smart-home/), [2025.8 release](https://rc.home-assistant.io/blog/2025/08/06/release-20258/)). The community **home-generative-agent** is directly analogous to this stack: LangGraph agent inside HA's single Python process, camera-motion triggers → video analysis with anomaly detection, pgvector-backed semantic memory, and a deterministic "Sentinel" rules engine where **"the LLM advises but never actuates"** safety-critical devices ([github.com/goruck/home-generative-agent](https://github.com/goruck/home-generative-agent)). The pattern everywhere in HA: **deterministic trigger, probabilistic interpretation, deterministic (or human-gated) actuation**.

### 6.2 Zapier / IFTTT

Trigger firing is either **polling (1–15 min interval by plan tier on Zapier; 15 min+ on many IFTTT applets)** or **instant webhooks**; Zapier Agents layer LLM steps over ~9,000 app triggers/actions ([codewords.ai](https://www.codewords.ai/blog/ifttt-vs-zapier), [zapier.com](https://zapier.com/blog/zapier-agents-guide/)). Practical takeaway: even at commercial scale, *polling at minutes-granularity is the default trigger substrate*; webhooks are the upgrade path per-source, not the baseline.

### 6.3 Postgres-only eventing — what actually holds up

- **LISTEN/NOTIFY**: zero-infra pub/sub, but three hard edges. (1) **Global commit serialization**: any transaction issuing NOTIFY takes an AccessExclusiveLock on the whole instance during commit (held through fsync) so queue entries appear in commit order — recall.ai traced three outages (2025-03-19→22) to this under heavy concurrent writes; a fix (commit 282b1cde) lands only in **PostgreSQL 19 (~Sept 2026)** ([recall.ai](https://www.recall.ai/blog/postgres-listen-notify-does-not-scale), [simonwillison.net](https://simonwillison.net/2025/Jul/11/postgres-listen-notify/)). (2) **8,000-byte payload cap** → send row IDs, not data ([stacksync.com](https://www.stacksync.com/blog/beyond-listen-notify-postgres-request-reply-real-time-sync)). (3) **Not durable** (offline listeners lose events) and **broken by PgBouncer transaction pooling** — use one dedicated unpooled listener connection ([dev.to](https://dev.to/software_mvp-factory/postgresql-listennotify-as-a-lightweight-job-queue-replacing-redis-for-your-startups-background-4g8j), [pedroalonso.net](https://www.pedroalonso.net/blog/postgres-listen-notify-real-time/)). The consensus safe pattern: **NOTIFY is a wake-up ping only; a jobs table is the source of truth**, drained with `SELECT ... FOR UPDATE SKIP LOCKED` — good to ~50K jobs/hour before a real broker is warranted ([dev.to](https://dev.to/software_mvp-factory/postgresql-listennotify-as-a-lightweight-job-queue-replacing-redis-for-your-startups-background-4g8j), [jusdb.com](https://www.jusdb.com/blog/postgresql-listen-notify-realtime-events)). At low write volume (a personal concierge) the global-lock issue is irrelevant; DBOS also argues it scales fine for most workloads ([dbos.dev](https://www.dbos.dev/blog/postgres-listen-notify-scalability)).
- **pg_cron**: in-database scheduler; since v1.5 supports **1–59 second intervals** in addition to cron syntax; with background workers, concurrency is bounded by `max_worker_processes` (default 8) vs `max_connections` (default 100) in connection mode; **only one instance of a given job runs at a time — a re-fire queues behind the running one** (free built-in overlap protection) ([github.com/citusdata/pg_cron](https://github.com/citusdata/pg_cron), [pgedge docs](https://docs.pgedge.com/pg-cron/development/)). For this platform it is a fallback: the in-process advisory-locked scheduler already covers it without requiring a DB extension.
- **Webhook receivers**: FastAPI route → verify signature → insert event row → NOTIFY/poll pickup. This is exactly Claude Routines' API trigger and Inbox Zero's Gmail push path, minus the hosting.

## 7. Trigger-architecture comparison

| Architecture | Fires how | State lives | Latency | Durability | Exemplars |
|---|---|---|---|---|---|
| **Server-side saved prompt + scheduler** | Platform cron vs stored schedule; new isolated run per fire | Task def + run history in vendor DB; no convo carryover (ChatGPT) or optional thread-bound (LangGraph) | Minutes (min interval 1h ChatGPT/Claude; hourly floors common) | High (managed) | ChatGPT Tasks, Gemini Scheduled Actions, Copilot scheduled prompts, Claude Routines, LangGraph crons |
| **Polling watcher ("monitoring task")** | Cron fires → agent fetches source → diff/judge significance → notify or stay silent | Last-seen cursor + judgment memory server-side | Poll interval (hourly ChatGPT; 1–15 min Zapier) | High | ChatGPT monitoring tasks, EAIA Gmail ingest, Zapier polling triggers |
| **Webhook / event push** | External system POSTs to per-resource endpoint; filters gate spawn | Event → new session/run; filters + caps in platform | Seconds | Medium (hourly caps drop excess — Claude Routines; missed-listener loss — LISTEN/NOTIFY) | Claude Routines API+GitHub triggers, Zapier instant, Inbox Zero, HA automations |
| **Continuous stream monitor** | Agent subscribed to full message/event stream; model itself decides act-vs-ignore | Channel-scoped memory at vendor | Near-real-time | High | Claude Tag ambient mode, Astra (prototype) |
| **Piggyback / activity-coupled** | Background agent fires every N steps of the primary agent or on context compaction | Shared memory blocks in agent DB | Coupled to user activity + idle | High | Letta sleep-time agents |
| **In-DB (broker-less)** | NOTIFY ping + SKIP LOCKED drain; pg_cron ticks | Jobs/events tables — same transactional store as app | Sub-second (NOTIFY) to seconds | High if table-backed; NOTIFY alone is fire-and-forget | recall.ai (pre-migration), countless Postgres-queue stacks |

Cross-cutting observations: (a) **every mainstream product converged on "new isolated run per fire" + result delivered as a new conversation/notification**, not resumption of an old chat; (b) **caps are small and universal** (3–15 tasks, 10 actions, 10 prompts, daily run caps) because each fire costs real inference; (c) the fully-autonomous "AI picks what to do" mode (Pulse) was retired in favor of user-declared standing intents; ambient stream-monitoring (Claude Tag) ships opt-in and enterprise-only.

## 8. Notification / interruption UX

- **Attention is the hard ceiling**: ~3–5 proactive notifications/user/day before mute/uninstall behavior; recovery from an interruption averages ~23 minutes; even 5-second interruptions triple error rates in complex work ([tianpan.co](https://tianpan.co/blog/2026-05-13-background-agents-notification-budget-attention-economy)).
- **Channel = urgency routing**: real-time push only for security/payments/approvals/outages; high-volume low-urgency → digest ("we'll keep you informed, just not interrupted"); per-category channel + frequency controls and absolute quiet hours ([appmaster.io](https://appmaster.io/blog/notification-preferences-quiet-hours-digests-tracking), [eleken.co](https://www.eleken.co/blog-posts/notification-ux)). Heuristic: a notification muted ≥25% of the time should be retired or downgraded a channel ([timgraf.com](https://timgraf.com/ux-design/notification-and-alert-design-patterns-a-comprehensive-ux-framework-for-designing-feedback-systems-that-respect-user-attention-drive-meaningful-engagement-and-prevent-notification-fatigue/)).
- **Significance gating inside the agent**: ChatGPT monitoring tasks notify only when the model judges the change significant ([aiweekly.co](https://aiweekly.co/alerts/openai-brings-scheduled-tasks-and-web-monitoring-to-chatgpt)); EAIA's triage node routes ignore/notify/draft before anything reaches the human ([executive-ai-assistant](https://github.com/langchain-ai/executive-ai-assistant)); proactive-agent guidance: honor quiet hours absolutely, accumulate observations into periodic briefings rather than per-item pings ([vanishlabs.ai](https://vanishlabs.ai/news/proactive-ai)).
- **HITL taxonomy**: LangChain's Notify / Question / Review triple, delivered through an Agent Inbox rather than chat, is the cleanest shipped model of "agent-initiated contact that isn't an interruption" — items wait; badges, not pushes ([langchain.com](https://www.langchain.com/blog/introducing-ambient-agents)).

## 9. Safety / guardrails for background autonomy

- **Structural blast-radius limits beat runtime judgment**: Claude Routines can't merge, can't push to protected branches or others' branches, and run behind a network allowlist — the most powerful action is opening a PR a human gates ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)). Home-generative-agent: LLM advises, deterministic rules actuate ([goruck/home-generative-agent](https://github.com/goruck/home-generative-agent)).
- **Confirmation for consequential actions** (Operator/agent mode: purchases, sending email) + watch/takeover modes for sensitive contexts ([help.openai.com](https://help.openai.com/en/articles/10421097)).
- **Runtime ceilings** as production practice: per-session spend caps (e.g. $0.50), 20 actions/min rate limits, 100 external calls/run, enforced in the orchestration layer, not the prompt ([vercel.com](https://vercel.com/i/five-ai-agent-guardrails-production), [traversaal.ai](https://blog.traversaal.ai/ai-agent-guardrails-defense-in-depth-architecture-guide/)).
- **Tool allowlists checked by the execution wrapper** per agent role; off-list calls dropped or escalated ([vercel.com](https://vercel.com/i/five-ai-agent-guardrails-production)). Deterministic policy engines outside the model's decision path — budgets, destination allowlists, signed short-lived mandates, hash-chained audit ledgers (MandateGuard pattern) ([awesome-ai-agent-governance](https://github.com/systempromptio/awesome-ai-agent-governance), [techarion.com](https://techarion.com/blog/ai-agent-governance-audit-trails-compliance)).
- **Trust labeling of trigger inputs**: Claude Routines' untrusted-payload wrapper is the shipped answer to injection-via-webhook ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).
- **Audit = every executed rule/action persisted** (Inbox Zero's Prisma ledger; Routines' full session transcripts; run status ≠ task success, transcript is the proof) ([inbox-zero ARCHITECTURE.md](https://github.com/elie222/inbox-zero/blob/main/ARCHITECTURE.md), [code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines)).

## 10. The 12 most transferable mechanisms for FastAPI + Postgres + LangGraph (single process)

1. **Routine-as-record** (Claude Routines): a `routines` table row = prompt + tool/skill scope (registry refs) + trigger specs + model choice. Every fire creates a fresh run in the runs ledger with a link back to the routine; the fired prompt is trusted because it was stored by an authorized session, while any fire-time payload is wrapped and labeled untrusted. ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines))
2. **Jobs table + `FOR UPDATE SKIP LOCKED` drain, with LISTEN/NOTIFY as a wake-up ping only** — durable queue in the store already present; NOTIFY carries a row ID (<8KB), a dedicated unpooled listener connection wakes the asyncio drainer instantly, and the scheduler's periodic sweep covers missed pings. At personal-agent write volume the PG global-commit-lock issue (fixed in PG 19) is not a factor. ([recall.ai](https://www.recall.ai/blog/postgres-listen-notify-does-not-scale), [dev.to](https://dev.to/software_mvp-factory/postgresql-listennotify-as-a-lightweight-job-queue-replacing-redis-for-your-startups-background-4g8j))
3. **Polling watchers with significance gating** (ChatGPT monitoring tasks, EAIA): standing intents compile to a poll job (cursor = last-seen ID/timestamp, lookback with early termination) plus an LLM "is this worth reporting?" judgment node — notify only above threshold, else append to digest. ([aiweekly.co](https://aiweekly.co/alerts/openai-brings-scheduled-tasks-and-web-monitoring-to-chatgpt), [executive-ai-assistant](https://github.com/langchain-ai/executive-ai-assistant))
4. **Triage-first graph topology** (EAIA/Inbox Zero): every ambient event enters through a cheap classifier node routing ignore / notify / act-with-approval / act-autonomously, per-rule automation level configurable by the user. ([executive-ai-assistant](https://github.com/langchain-ai/executive-ai-assistant), [inbox-zero](https://github.com/elie222/inbox-zero))
5. **Agent Inbox + Notify/Question/Review HITL vocabulary** (LangChain): agent-initiated items land in an inbox backed by interrupt-over-checkpoint — state pauses durably until the human responds; the existing HITL approval gates are the Review lane, and Notify/Question are cheaper lanes that don't block a run. ([langchain.com](https://www.langchain.com/blog/introducing-ambient-agents), [docs.langchain.com](https://docs.langchain.com/oss/python/langchain/human-in-the-loop))
6. **Fresh-thread-per-fire with explicit retention** (LangGraph stateless crons): default delete-style cleanup of ambient run threads with an opt-in keep + TTL, so scheduled runs don't accrete unbounded checkpoints. UTC-only schedule storage with local-time conversion at the edge. ([docs.langchain.com](https://docs.langchain.com/langgraph-platform/cron-jobs))
7. **Idle-coupled sleep-time processing** (Letta): trigger consolidation every N completed run-steps *and* on idle detection, with the consolidator as a separate agent that owns memory writes the chat agent can't make; optionally a second review pass before applying memory edits. Justify the spend with the 5×-test-time-compute / +13–18% accuracy numbers. ([docs.letta.com](https://docs.letta.com/guides/agents/architectures/sleeptime/), [arxiv.org](https://arxiv.org/html/2504.13171v1))
8. **Per-routine bearer-token webhook endpoints** (Claude Routines): `POST /routines/{id}/fire` with a one-time-shown, revocable token; freeform `text` payload wrapped as untrusted; response returns the run ID/URL so the caller can watch. Filters (field + operator incl. regex-anchored) gate which events spawn runs; per-routine hourly caps drop excess events. ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines))
9. **Small hard caps + stagger** (everyone): cap active routines (3–15 range is industry-normal), cap runs/day, floor the schedule interval (1h at OpenAI/Anthropic; a local platform can afford minutes), auto-pause unattended tasks after inactivity, and give each routine a consistent random stagger offset so schedules don't align. ([help.openai.com](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt), [code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines))
10. **Notification budget + digest ledger**: enforce ~3–5 proactive pushes/day and absolute quiet hours in a delivery policy layer; sub-threshold items accumulate in a Postgres digest table rendered as a morning-brief card view (the part of Pulse that survived); track mute/dismiss rates per category and auto-downgrade noisy categories. ([tianpan.co](https://tianpan.co/blog/2026-05-13-background-agents-notification-budget-attention-economy), [appmaster.io](https://appmaster.io/blog/notification-preferences-quiet-hours-digests-tracking), [prowlo.com](https://prowlo.com/blog/chatgpt-pulse-shut-down))
11. **Structural guardrails outside the model**: ambient runs get a *narrowed* registry projection (explicit tool allowlist per routine, connectors/tools removable at creation), deterministic per-run ceilings (spend, action count, wall-clock) enforced by the orchestration layer, and consequential-action classes that always route through the approval gate — "LLM advises, gate actuates." ([vercel.com](https://vercel.com/i/five-ai-agent-guardrails-production), [code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines), [goruck/home-generative-agent](https://github.com/goruck/home-generative-agent))
12. **Run-status honesty + agent-as-debugger**: distinguish "run completed without infrastructure error" from task success in the ledger; keep full transcripts; expose a "why did my nightly routine do nothing?" query that reads the ledger and explains tool errors/permission denials. ([code.claude.com/docs/en/routines](https://code.claude.com/docs/en/routines))

Anti-patterns the record warns against: fully-opaque autonomous topic selection (Pulse retired ([prowlo.com](https://prowlo.com/blog/chatgpt-pulse-shut-down))); ambient-on-by-default (Claude Tag ships it opt-in with "start disabled" guidance ([usecarly.com](https://www.usecarly.com/blog/claude-slack-integration/))); shipping-then-pulling a scheduler without an operating model (Copilot Actions ([perspectives.plus](https://www.perspectives.plus/p/the-secret-life-of-copilot-scheduled-prompts))); relying on bare LISTEN/NOTIFY as the queue rather than the wake-up ([recall.ai](https://www.recall.ai/blog/postgres-listen-notify-does-not-scale)).
